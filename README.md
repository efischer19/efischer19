# Hi, I'm Eric

Staff backend engineer, 14 years in. I build and run the platforms that other teams depend on: hundreds of millions of records, and a lot of people asking "is it down?" I'm the one who finds the root cause, at whatever layer it's hiding, and then makes sure it stays fixed.

Most of what's public here is a deliberate practice in **directing AI coding agents well**. Architecture decision records are the guardrails, issues are the spec, CI is the quality gate, and I act as architect and reviewer.

**Things that work**
- **[woodwire](https://github.com/efischer19/woodwire)**: secure, event-driven chat between a static PWA and a fully-local AI agent. Zero-trust edge, SQS/S3 message flow, no open ports. I use it every day.
- **[whassat](https://whassat.info)** ([repo](https://github.com/efischer19/whassat)): fully offline object detection in the browser, in under 6MB. Built by hand in 2019, when my kid started pointing at everything and asking what it was.
- **[Blueprint templates](https://github.com/efischer19/blueprint-repo-blueprints)**: a family of GitHub template repos that turn lessons learned into paved roads, from "use ADRs" up to an empty repo → a deployed AWS data pipeline.
- **[Commit Hygiene](https://gist.github.com/efischer19/5d05178edd20054b3a9d85bd656f54f2)**: why and how I curate commits and pull requests.

**Works in progress**: [hoopstat-haus](https://github.com/efischer19/hoopstat-haus) (an NBA/WNBA stats lakehouse; the daily build runs, but much of the design is still ahead of the code) and [scrymat](https://github.com/efischer19/scrymat) (a peer-to-peer Magic: The Gathering playmat). Each README has an honest status section.

**Earlier:** [reactifex](https://github.com/efischer19/reactifex) (~660k npm downloads, part of Open edX's frontend platform) and a few hundred merged PRs across [Open edX](https://github.com/openedx).
